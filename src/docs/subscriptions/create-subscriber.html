Create Subscriber

The create subscriber API call will return a link to a payment page, where the customer can enter their payment details (i.e. subscribe). When the customer has subscribed, you can retrieve a subscriber ID through the Synchronization API.

Request

POST
https://api.scanpay.dk/v1/new

Request Body

All request fields are listed below. All fields except subscriber are optional.

JSON fields Description
"orderid": "395" A unique ID that you choose. Never reuse IDs or your synchronization may behave in unexpected ways.
"successurl": "http://blixen.dk/success" Redirect to this URL after succesful payment. If omitted we will show a generic success message. 
{% include "docs/subscriptions/code/subscriber-ref.txt" %}
 This object tells us that you want to create a subscriber. The object is required, but you can leave it empty:
  • ref: A reference to the subscriber in your system.
 
{% include "docs/payment-links/code/billing.json" %}

Customer billing and shipping address.

  • name: The full name.
  • company: Legal company name.
  • vatin: EU VAT identification number.
  • gln: Global Location Number or European Article Numbering (EAN-number).
  • email: E-mail address.
  • phone: Phone number with country prefix.
  • address: An address array where each element is a new line.
  • zip: Postal code.
  • city: City.
  • state: State or region.
  • country: Two-letter country code (ISO 3166-1).
"language": "da" Preferred language for the payment window. We fallback to the Accept-Language header.
"lifetime": "2d 12h 30m" Set payment link lifetime in days (d), hours (h) or minutes (m). Default is "1h" and max is "30d"

Response

Success

Successful requests return status code 200 and a JSON object:

JSON fields Description
"url": "https://betal.scanpay.dk/9qdvbx2r" The payment link. You can redirect the customer to this URL to complete the payment.

Errors

Failed requests return an HTTP error code and a error message in the HTTP body:

Code HTTP Body Description
400 invalid json Invalid JSON.
403 invalid apikey Invalid API key.
408 Request Timeout The request timed out after 8 seconds.
413 Request Entity Too Large The request body was larger than 32 kB.
400 Request Header Or Cookie Too Large The request HTTP headers were larger than 4 kB
500 internal server error Technical issue at Scanpay. Please try again later.
